# RFP-RAG

> 코드잇 AI 중급 프로젝트 · 3팀
>
> RFP(제안요청서) 문서 기반 정보 검색·요약 및 질의응답 시스템

## 프로젝트 목표

- RFP 문서에서 필요한 정보를 검색하고, 문서에 근거한 답변을 제공하는 RAG 시스템을 구축합니다.
- 주요 요구 조건, 발주 기관, 예산, 제출 방식 등을 파악하여 입찰 검토 업무를 돕습니다.
- 실험과 의사결정을 기록하고 공유하며, 팀 프로젝트를 통해 함께 성장합니다.

## 프로젝트 개요

공공입찰 컨설팅 서비스 ‘입찰메이트’의 사내 RAG 시스템 구축을 주제로 진행하는 프로젝트입니다. 컨설턴트가 수십 페이지의 제안요청서를 일일이 읽는 부담을 줄이고, 고객사에 적합한 입찰 기회를 검토하는 데 필요한 정보를 제공하는 것을 목표로 합니다.

제공된 RFP 문서 100개와 메타데이터를 활용하여 문서 처리, 청킹, 임베딩, 검색, 답변 생성 및 성능 평가를 진행합니다.

| 항목 | 내용 |
| --- | --- |
| 입력 데이터 | RFP 문서(HWP, PDF), `data_list.csv` 메타데이터 |
| 주요 기능 | 문서 기반 정보 검색, 핵심 내용 요약, 질의응답, 대화 맥락 유지 |
| 비교 실험 | GCP에서 직접 실행하는 모델과 LLM API 기반 방식 |
| 최종 산출물 | 재현 가능한 코드, 분석 보고서, 개인별 협업일지 |

### 협업일지

개인별 협업일지 링크는 위 팀원 표에 추가할 예정입니다. 일지에는 수행한 작업, 문제와 해결 과정, 의사결정의 이유, 배운 점, 다음 작업 및 도움이 필요한 사항을 기록합니다.

### Git 협업 규칙

| 브랜치 | 용도 |
| --- | --- |
| `main` | 검증을 마친 안정화 버전 |
| `dev` | 기능 통합 및 테스트 |
| `feature/*` | 새로운 기능 및 실험 개발 |
| `fix/*` | 오류 수정 |

1. `dev`에서 작업 브랜치를 생성합니다.
2. 작업 완료 후 `dev`를 대상으로 Pull Request를 생성하고 검토 후 병합합니다.
3. `dev`에서 통합 테스트를 수행한 뒤, 안정화된 변경 사항을 Pull Request로 `main`에 반영합니다.

커밋 메시지는 `타입: 변경 내용` 형식을 사용합니다. 예: `docs: README 프로젝트 개요 작성`
