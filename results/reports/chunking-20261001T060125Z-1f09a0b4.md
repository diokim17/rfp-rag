# 청킹 오프라인 비교

- 범위: 동일 CSV 앞 3행에서 정상 추출된 HWP 3개. 파싱은 한 번만 수행.
- 변경: 청킹 전략 fixed → boundary(version=1), 임베딩 응답 검증 및 수치 안정성 강화.
- 유지: 1000자/150자 중복, 문서 순서·내용, 공개 시그니처 및 기존 필수 키.
- 임베딩 모델·배치(32)·FAISS 형식은 코드상 유지. 이 실험에서는 임베딩/검색/생성 미실행.
- 실제 API 호출 0회. 실제 토큰·Recall·답변 품질은 미측정. 아래 구조 지표는 검색 품질 향상 근거가 아님.
- 오프라인 재현을 위해 parse 실행에만 LANGFUSE_ENABLED=false를 명시. 기존 추적 구현은 유지.

## 검증·실패 사례·한계

- 기존 테스트 13개와 새 테스트 18개: 총 31개 통과. pip check 통과.
- fixed는 변경 전 HEAD 함수가 만든 실제 문서 청크와 완전히 일치.
- 두 전략 모두 원문 슬라이스 일치·비공백 문자 커버리지 100%, 최대 길이 준수 확인.
- 모의 API로 잘못된 index/벡터, 배치 차원 불일치·중간 실패 시 기존 파일 보존, 65개 입력의 32/32/1 배치 순서, 과거 config 호환과 전체 파이프라인 연결 확인.
- 모의 추적의 토큰 합산·본문/파일명/기관명 제외 확인. 모의 API 점수는 실제 성능에서 제외.
- 경계가 없는 긴 문자열은 고정 길이로 분할. 높은 overlap에서는 짧은 경계를 무시하고 항상 전진.
- boundary는 경계 탐색 비용과 청크 수·중복량을 늘릴 수 있음. 문자 중복 시작점은 문장 중간일 수 있음.
- 표 구조 복원·토큰 상한·의미적 근거 완결성·실제 API 성공 여부는 보장하지 않음. HWP 3개 밖의 문서와 PDF는 추가 검증 필요.
- 원문으로 정답을 검증한 평가셋을 고정하고, 문서/질문 수와 호출량 협의 후 Recall·키워드 포함률·실제 토큰·전체 지연 비교 필요.
- 새 전략을 사용하려면 별도 인덱스를 build해야 함. 기존 fixed 인덱스는 재사용 가능. 인덱스 저장의 원자적 교체는 이번 범위 밖.

## 오프라인 재현

먼저 충돌하지 않는 폴더 이름을 선택합니다. 폴더 이름은 실험 ID가 아닙니다. 기존 산출물을 재사용하면 parse를 생략합니다. owner는 개인 .env의 EXPERIMENT_OWNER를 사용합니다.

```bash
export PROCESSED_DIR="data/processed/chunking-20261001T060125Z-1f09a0b4"
# 다른 원본으로 재실행할 때는 먼저 새 PROCESSED_DIR를 지정하세요.
# LANGFUSE_ENABLED=false .venv/bin/python run.py parse --limit 3 --processed-dir "$PROCESSED_DIR"
.venv/bin/python - <<'PY'
import hashlib
import json
import os
from pathlib import Path
import statistics
import time
import numpy as np
from embedding import chunk_documents
from parsing import read_json

path = Path(os.environ['PROCESSED_DIR']) / 'documents.json'
documents = read_json(path)
by_id = {d['doc_id']: d['text'] for d in documents}
assert len(documents) == 3
assert len(by_id) == len(documents)
metrics, chunks_by_strategy = {}, {}
for strategy in ('fixed', 'boundary'):
    os.environ['RFP_CHUNKING_STRATEGY'] = strategy
    chunks = chunk_documents(documents, 1000, 150)
    chunks_by_strategy[strategy] = chunks
    lengths, covered = [], {key: set() for key in by_id}
    internal, paragraph_ends, line_ends = 0, 0, 0
    for chunk in chunks:
        text = by_id[chunk['doc_id']]
        start, end = chunk['metadata']['start_char'], chunk['metadata']['end_char']
        assert chunk['text'] == text[start:end]
        assert 0 <= start < end <= len(text) and end - start <= 1000
        lengths.append(end - start)
        covered[chunk['doc_id']].update(range(start, end))
        if end < len(text):
            internal += 1
            paragraph_ends += text[:end].endswith('\n\n')
            line_ends += text[:end].endswith('\n')
    for key, text in by_id.items():
        assert {i for i, c in enumerate(text) if not c.isspace()} <= covered[key]
    metrics[strategy] = {
        'chunking_version': 1, 'chunks': len(chunks),
        'length_min': min(lengths), 'length_median': statistics.median(lengths),
        'length_p95': float(np.percentile(lengths, 95)), 'length_max': max(lengths),
        'total_chunk_chars': sum(lengths),
        'duplicate_chars': sum(lengths) - sum(len(v) for v in covered.values()),
        'internal_ends': internal,
        'paragraph_end_percent': 100 * paragraph_ends / internal,
        'line_end_percent': 100 * line_ends / internal,
        'estimated_build_requests_at_32': (len(chunks) + 31) // 32,
        'non_whitespace_coverage_percent': 100,
    }
# 워밍업 10회 뒤 두 전략의 순서를 교대로 바꾸며 각 101회 측정합니다.
for _ in range(10):
    for strategy in metrics:
        os.environ['RFP_CHUNKING_STRATEGY'] = strategy
        chunk_documents(documents, 1000, 150)
samples = {strategy: [] for strategy in metrics}
for repeat in range(101):
    order = ('fixed', 'boundary') if repeat % 2 == 0 else ('boundary', 'fixed')
    for strategy in order:
        os.environ['RFP_CHUNKING_STRATEGY'] = strategy
        start = time.perf_counter()
        chunk_documents(documents, 1000, 150)
        samples[strategy].append((time.perf_counter() - start) * 1000)
for strategy in metrics:
    metrics[strategy]['median_chunking_ms'] = statistics.median(samples[strategy])
summary = {'documents_sha256': hashlib.sha256(path.read_bytes()).hexdigest(),
           'documents': len(documents), 'source_chars': sum(map(len, by_id.values())),
           'chunk_size': 1000, 'chunk_overlap': 150, 'warmups': 10, 'repeats': 101,
           'actual_api_calls': 0, 'actual_api_tokens': None, 'retrieval_quality': None,
           'strategies': metrics}
print(json.dumps(summary, ensure_ascii=False, indent=2))
PY
```

## 후속 유료 비교용 명령 (이번에는 실행하지 않음)

동일 평가셋과 top_k, 답변 모델을 고정하고 API 호출량·비용을 협의한 뒤 실행합니다. 명령마다 실험 ID가 자동 생성됩니다.

```bash
export PROCESSED_DIR="data/processed/chunking-20261001T060125Z-1f09a0b4"
for strategy in fixed boundary; do
  RFP_CHUNKING_STRATEGY="$strategy" .venv/bin/python run.py build --processed-dir "$PROCESSED_DIR" --index-dir "indexes/chunking-20261001T060125Z-1f09a0b4/$strategy" --chunk-size 1000 --chunk-overlap 150
  .venv/bin/python run.py evaluate --processed-dir "$PROCESSED_DIR" --index-dir "indexes/chunking-20261001T060125Z-1f09a0b4/$strategy" --results-dir "results/chunking-20261001T060125Z-1f09a0b4/$strategy" --eval-file data/eval.json --top-k 5
done
```

자동 평가 보고서는 전략 키를 출력하지 않으므로 전략/version과 비교 조건을 별도 요약에 명시합니다. 청킹 변경은 build → evaluate가 필요하며 같은 파싱 결과는 재사용합니다.
