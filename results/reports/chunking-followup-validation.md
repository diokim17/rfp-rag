# 구조 청킹 100문서 검증 및 목차 경계 퇴행 수정

2026-10-06 UTC. 승인된 범위: 같은 100문서 후보 1개 생성 → smoke 6문항 → 통과 시 sample 14문항.

후속 상태: 별도 승인으로 v2의 변경 청크와 영향 문항을 검증해 f01 답변 회복을 확인했다. [v2 최종 검증 보고서](chunking-revision2-validation.md)를 참고한다. 아래는 v1 평가와 v2 유료 검증 전의 기록이다.

**판정: structured/none v1은 표 보존과 일부 검색 지표가 개선됐지만 새 답변 퇴행이 있어 기본값으로 채택하지 않는다.**
실패 원인을 확인해 v2 경계 처리를 로컬에서 수정했으며 79개 테스트와 100문서 오프라인 검증을 통과했다.
v2의 유료 검색·답변 검증은 아직 수행하지 않았다. 이번 승인 범위에서 실제 호출은 총 380회다.

## 비교 조건

baseline fixed/none과 후보 structured/none은 같은 documents.json의 100문서, 같은 smoke/sample 평가 파일을 사용했다.
문서 SHA-256: `97bb7a5afa3219566047e817fa6125617d7fd18fe3df52285785f070eed9807a`.
임베딩 text-embedding-3-small / 1536차원, 생성 gpt-5-mini / reasoning low / max_output_tokens 2000,
chunk_size 1000, chunk_overlap 150, top-k 5, 문항별 필터를 유지했다. 변경한 품질 조건은 청킹 전략 하나다.
기본 설정 fixed/none, 기존 인덱스, run.py·검색·생성·평가 구현은 이번 작업에서 변경하지 않았다.

baseline 답변은 앞서 생성한 chy-0004(smoke), chy-0005(sample)를 재사용했다.
후보는 같은 질문 벡터를 캐시에서 사용하고 sample의 미캐시 질문 8개만 새로 임베딩했다.
따라서 응답 시간의 측정 구간에서 baseline은 질문 임베딩 호출을 포함하지만 후보는 포함하지 않는다.
생성 결과도 각 1회 측정이며 서버 지연·모델 출력 변동을 통제하지 않았다. 속도 개선이나 통계적 유의성을 주장하지 않는다.
smoke 6문항은 sample에 포함된다. 총 20개 답변을 생성했지만 독립된 질문은 14개다.

## f01 원인과 후속 v2 수정

기존 fixed 첫 청크 [0,1000)는 제목과 기간·예산을 함께 담아 검색 2위였다.
structured v1은 첫 실제 섹션 위치 629에서 잘라 제목·목차만 있는 [0,629) 청크가 2위가 됐다.
기간·예산을 포함한 [479,1173) 청크는 28위로 밀렸다. 사업명 메타데이터 손실은 없었다.

embedding.py의 structured 경계 처리에 제한된 예외를 추가했다. 첫 청크의 후반에 첫 섹션이 있고 그 앞에 독립된
목차 제목이 있으면, 그 섹션 바로 앞에서 자르는 대신 기존 문단 경계를 사용한다. 크기·표·제목 보호 규칙은 유지한다.
문서 ID나 특정 사업명·기간 문자열을 조건으로 사용하지 않는다. 인라인 문장의 “목차” 단어는 이 예외를 활성화하지 않는다.

- f01 첫 청크가 [0,789)로 바뀌어 제목·기간·예산이 함께 포함됐다.
- 같은 100문서에서 실제 변경은 **1문서의 2청크**뿐이다. 총 청크 수 11,844개는 유지된다.
- 기존 벡터를 재사용할 수 있는 청크는 **11,842개**이며 새 입력 2개는 합계 1,290자다. 토큰 수와 동일하지 않다.
- fixed/boundary 출력은 평가 당시 구현과 정확히 같고, 원문 누락·좌표·크기·메타데이터·표 보존 검증을 통과했다.
- structured의 chunking_version을 2로 올렸다. fixed/boundary 버전 1, 공개 함수와 기본값, documents_sha256 전달·저장 계약은 유지했다.
- 신규 4개 회귀 테스트를 포함해 **79개 통과**. LF/CRLF·목차 표기·인라인 오탐·일반 섹션·표·큰 overlap·저장 버전을 확인했다.
  합성 실패 재현에서 v1은 첫 청크의 기간을 누락하고 v2는 보존함을 확인했다.
- pip check와 git diff --check 통과. 패키지 설치나 공통 모듈 변경은 없다.

이 수정은 **아직 검색 순위와 답변 회복을 입증하지 않았다.** 위 유료 성능 표는 수정 전 v1의 결과다.
수정본을 평가하려면 별도 v2 인덱스를 만들어야 한다. 신규 2청크 임베딩 1회와 f01 답변 생성 1회로 최소 확인이 가능하며,
전체 14문항의 캐시 질문으로 검색 결과 변화를 먼저 확인해 다른 영향 문항의 추가 답변 평가 필요성을 판단해야 한다.
이번에는 승인된 380회 범위 이후의 추가 API 호출을 하지 않았다.

## f08 진단과 담당 범위

누락 사업의 첫 검색 순위는 baseline 11위, structured v1 17위다. 같은 질문 벡터로 기존 기관 필터를 적용하면 두 인덱스 모두
정답 2개 문서를 top-5에서 찾는다. 이는 추가 API 없이 수행한 검색 진단이며 평가셋이나 공식 점수를 변경한 결과가 아니다.
질문에서 기관 필터를 적용하는 연결 또는 목록 검색의 다양성 처리는 검색·통합 담당자와 협의할 범위다. 관련 모듈은 수정하지 않았다.
