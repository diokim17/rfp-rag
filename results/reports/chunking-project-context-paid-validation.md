### 실패 근거와 해석

- s02의 누락된 계약 표현은 정답 문서의 후보 청크 5개에 존재하지만 검색된 5개 본문에는 없었다.
- s04의 세부 금액은 정답 문서의 후보 청크 1개에 존재하지만 상위 5개에 포함되지 않았다.
- s05의 담당 부서는 정답 문서의 후보 청크 4개에 존재하지만 상위 5개에 포함되지 않았다.

따라서 이번 3건은 단순한 키워드 표기 차이로만 보기 어렵다. 모델도 해당 항목을 확인할 수 없다고 답했으며, 필요한 근거가 검색 결과에서 빠졌음을 로컬 답변·근거 비교로 확인했다. 후보 인덱스에 해당 내용이 남아 있어 원문 유실은 아니다.

정답 사업의 문서를 더 많이 검색하는 것과 그 문서 안에서 질문에 필요한 청크를 검색하는 것은 별개의 문제다. 문서 Recall@5는 후자를 측정하지 못해 이번 퇴행을 감지하지 못했다. 사업명 접두부가 내용보다 강하게 작용했을 가능성은 있으나 **청킹과 문맥을 동시에 변경했으므로 어느 변경이 원인인지 확정할 수 없다.**

## 후속 판단과 재현

현재는 baseline을 유지한다. sample 추가 실행이나 반복 생성만으로 이 후보를 통과시키지 않는다. 다음 개선은 정답 문서뿐 아니라 필요한 근거 청크의 포함 여부를 함께 관찰하고, `fixed/project`와 `structured/none`처럼 변경 요인을 분리해 판단하는 방향이 적합하다. 추가 유료 인덱스 생성·평가는 별도 범위 협의가 필요하며 이번에는 수행하지 않았다.

후보 인덱스는 이미 생성되어 있어 향후 같은 후보의 평가 재실행에 build는 필요 없다. 아래 명령은 추가 API 비용이 발생하며 이번 작업에서 다시 실행하지 않았다.

```bash
OPENAI_GENERATION_MODEL=gpt-5-mini .venv/bin/python run.py evaluate \
  --processed-dir data/processed/chy-project-context-20261006T043827593755Z \
  --index-dir indexes/chy-project-context-20261006T043827593755Z/structured-project \
  --results-dir results/chy-project-context-20261006T043827593755Z/structured-project \
  --eval-file data/eval_smoke_v0.json --top-k 5
```

기존 기본 인덱스는 `indexes/`에 그대로 있다. 이번 실험 때문에 parse를 재실행하거나 기존 인덱스를 복구할 필요는 없다. 코드 테스트 57개 통과와 오프라인 표 보존 검증은 [기존 구현 보고서](chunking-project-context-validation.md)에 기록되어 있으며, 이번 유료 검증 중에는 구현 변경이 없어 재실행하지 않았다.
